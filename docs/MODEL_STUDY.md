# 모델 조사·실험 규약 (팀원 4명 공통)

각자 논문 하나를 맡아 **같은 입력·같은 지표**로 Kaggle T4에서 돌리고 결과를 모은다.
조건이 다르면 비교가 안 된다. 아래 "바꾸지 말 것"을 지키면 결과가 한 표로 합쳐진다.

이미 끝난 모델(CatVTON, HR-VITON, 하이브리드, FASHN, FitDiT)의 결과와 판단 근거는 `docs/PLAN.md` F절에 있다.
**같은 실수를 반복하지 않도록 맡은 모델과 비슷한 항목을 먼저 읽을 것.**

---

## 1. 모델 고르기 (각자)

논문은 각자 찾는다. 고를 때 **반드시** 확인할 것:

| 확인 | 안 되면 |
|---|---|
| 코드와 **가중치**가 공개돼 있는가 | 못 돌린다. 논문만 있는 건 제외 |
| **추론 코드**가 있는가 (학습 코드만 있는 경우가 많다) | 제외 |
| **T4 16GB**에 들어가는가 (파라미터 수·권장 VRAM 확인) | FLUX·Qwen 계열(120억~200억)은 T4에 안 들어간다 → A100을 빌릴 때로 미룬다 |
| 라이선스 | 비상업이어도 괜찮다(우리는 비상업 용도). 확인만 해서 적어둘 것 |
| 이미 우리가 한 모델인가 | CatVTON·HR-VITON·FASHN·FitDiT는 `docs/PLAN.md` F절에 결과가 있다. 중복 금지 |

**겹치지 않게 미리 공유할 것.** 정해지면 이 표에 적는다.

## 1-2. 논문 리뷰 (실험과 함께 제출)

실험만 돌리면 "돌려봤다"로 끝난다. **왜 그런 결과가 나왔는지**를 논문으로 설명할 수 있어야 발표가 된다.
아래 7개 항목을 각 반 쪽~한 쪽 분량으로 채운다.

```markdown
### <모델 이름> 논문 리뷰 (담당: 이름)

1. **무슨 문제를 풀려고 했나** — 기존 방법의 어떤 한계를 지적하며 나왔는가
2. **핵심 아이디어 한 문장** — 이 논문이 새로 한 것 딱 하나
3. **구조** — 입력부터 출력까지 무엇을 거치는가 (마스크를 쓰는가, 옷을 먼저 변형하는가,
   포즈·부위 인식이 필요한가, 베이스 모델은 무엇인가)
4. **학습 데이터** — VITON-HD / DressCode / 자체 데이터. 몇 장인가.
   **우리 사진(실내 복도·흰 벽, 폰 촬영)과 얼마나 다른가**가 중요하다
5. **논문이 주장하는 성능** — 어떤 지표로 무엇과 비교했는가 (FID·SSIM·사람 평가 등)
6. **한계** — 논문이 스스로 인정한 것 + 우리가 보기에 의심스러운 것
7. **우리 프로젝트에 쓴다면** — 장점, 단점, 예상되는 실패 조건

⚠️ 5번은 그대로 믿지 말 것. 논문 수치는 자기들이 만든 조건에서 나온 값이고,
우리는 **실제 폰 사진**으로 확인한다. 그 차이를 적는 게 이 리뷰의 핵심이다.
```

실험 결과와 리뷰를 맞춰 보면 이런 문장이 나온다 — 이게 발표에서 쓸 내용이다.
> "논문은 마스크 없이 생성해 옷 볼륨이 자유롭다고 주장했는데, 실제로 오버핏 옷에서 그 장점이 확인됐다."
> "논문이 흰 배경 스튜디오 데이터로만 학습해서, 복도 배경 사진에서는 성공률이 떨어졌다."

## 2. 바꾸지 말 것 (공통 입력)

Kaggle 데이터셋 `jefferyjung/vfa-person-full`, `vfa-set2`, `vfa-real-garments` 에 다 있다.

투톤 라글란에 큰 프린트 티 + 회색 와이드 팬츠를 입고 있다. **원래 옷이 결과에 비치는지** 보기 좋은 조건이다.

|---|---|---|---|

| 카키 반팔 | `garment_tee_khaki.jpg` | 상의 | 단색·말린 소매단. 기본 성능과 질감 확인 |

## 3. 측정 항목

### 숫자 (커널이 자동으로 CSV에 기록)
| 항목 | 방법 |
|---|---|
| **장당 시간(초)** | 워밍업 1장을 버리고 측정. 모델 로딩·설치 시간은 따로 |
| **최대 GPU 메모리(GB)** | `torch.cuda.max_memory_allocated()` |
| 모델 로딩 시간(초) | 가중치를 GPU에 올리는 데 걸린 시간 |
| 가중치 용량(GB) | 다운로드 총량 |
| 출력 해상도 | 예: 576x768 |
| 설치 성공 여부 | 막힌 지점과 해결책을 `docs/ENVIRONMENT.md` 형식으로 적을 것 |

### 품질 (눈으로 판정, 6장 각각)
아래 6개 항목을 **O / △ / X** 로 적는다. 원본 옷 사진과 나란히 놓고 볼 것.

| 항목 | O 기준 |
|---|---|
| **색** | 원본 옷 색과 같다 (연해지거나 톤이 바뀌지 않음) |
| **프린트·무늬** | 그림/글자의 형태가 알아볼 수 있게 나온다 |
| **실루엣** | 소매 길이·기장·품이 원본 옷과 같다 |
| **없던 것** | 원본에 없는 주머니·덮개·단추가 생기지 않았다 |
| **원래 옷 흔적** | 입고 있던 옷이 비치거나 남지 않았다 |
| **사람·배경 보존** | 얼굴·손·바지·배경이 뭉개지지 않았다 |

**판정은 반드시 원본 해상도로 잘라서 볼 것.** 썸네일로 보고 "괜찮다"고 했다가 뒤집힌 적이 있다(F-7).

## 4. 커널 만들기

`kaggle_model_template/run_template.py` 를 복사해서 쓴다. 측정·CSV·입력 찾기가 이미 들어 있고,
**TODO 표시된 3곳**(설치, 모델 로딩, 추론 호출)만 맡은 모델에 맞게 채우면 된다.

```sh
cp -r kaggle_model_template kaggle_<모델이름>
# run_template.py 를 run_<모델이름>.py 로 바꾸고 kernel-metadata.json 의 id/title/code_file 수정
PYTHONUTF8=1 kaggle kernels push -p kaggle_<모델이름> --accelerator NvidiaTeslaT4
PYTHONUTF8=1 kaggle kernels status jefferyjung/vfa-<모델이름>
```

### 자주 걸리는 함정 (이미 겪은 것들)
- **`PYTHONUTF8=1` 없으면** 한글 때문에 cp949 오류가 난다(Windows).
- **clone·가중치는 `/kaggle/tmp`, 결과만 `/kaggle/working`.** 안 그러면 output이 수천 개 파일이 된다.
- **정밀도를 직접 지정할 것.** T4·P100은 bf16을 흉내만 내서 가장 느리다. fp16이 fp32보다 4배 빠르고 결과는 같았다(F-13·F-14).
- **T4 메모리가 모자라면** CPU offload를 쓴다. 단 offload는 CPU RAM을 12GB 이상 먹어서 **GPU 2장 동시 사용이 안 된다**(F-15).
- **구버전 패키지를 깔면** Kaggle 기본 패키지와 충돌한다. 필요한 것만 최소로 고정할 것(F-15 v1 실패 사례).
- **실행 시간이 12시간을 넘으면** 커널이 죽는다. 6장이면 문제없다.

## 5. 제출물

각자 아래 셋을 낸다.

1. **커널 폴더** — `kaggle_<모델이름>/` (코드 + kernel-metadata.json)
2. **결과** — `results.csv` + 이미지 6장 (`data/samples/results/<모델이름>/`, 커밋하지 않고 공유 폴더로)
3. **한 장 요약** — `docs/PLAN.md` 에 넣을 형식으로. 아래 틀을 그대로 채운다

```markdown
### <모델 이름> (담당: 이름, 날짜)

논문/저장소: <링크>. 구조 한 줄 설명. 라이선스.
커널 `kaggle_<이름>/`, 설정: <정밀도·스텝·guidance 등>

| 항목 | 값 |
|---|---|
| 장당 시간 | ○초 (T4) |
| 최대 GPU 메모리 | ○GB |
| 가중치 용량 | ○GB |

품질 (6장): 색 ○/6, 무늬·디테일 ○/6, 실루엣 ○/6, 없던 것 ○/6, 원래 옷 흔적 ○/6, 보존 ○/6

```

## 6. 비교 기준선 (FASHN, 현재 주력)

**위 공통 조건 그대로 측정한 값이다**(2026-09-21, 커널 `kaggle_fashn_t4x2/` M 묶음).
각자 결과를 이 숫자·판정과 1:1로 비교하면 된다. 결과 이미지: `data/samples/results/fashn_baseline/_M_baseline.jpg`

| 항목 | 값 |
|---|---|
| 설정 | fp16 · 25스텝 · guidance 2.5 · torch.compile |
| **장당 시간** | **49~52초** (셔츠 49.0/49.2, 카키 51.5/51.6, 팬츠 50.4/51.2) |
| 최대 GPU 메모리 | 3.2GB |

| 가중치 용량 | 약 2GB |
| 출력 해상도 | 576x768 (입력 사진 비율로 되돌려 저장) |

**품질 (6장)**
| 옷 | 색 | 무늬·디테일 | 실루엣 | 없던 것 | 원래 옷 흔적 | 보존 |
