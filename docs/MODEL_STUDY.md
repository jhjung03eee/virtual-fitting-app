# 모델 조사·실험 규약 (팀원 4명 공통)

각자 논문 하나를 맡아 **같은 입력·같은 지표**로 Kaggle T4에서 돌리고 결과를 모은다.
조건이 다르면 비교가 안 된다. 아래 "바꾸지 말 것"을 지키면 결과가 한 표로 합쳐진다.

이미 끝난 모델(CatVTON, HR-VITON, 하이브리드, FASHN, FitDiT)의 결과와 판단 근거는 `docs/PLAN.md` F절에 있다.
**같은 실수를 반복하지 않도록 맡은 모델과 비슷한 항목을 먼저 읽을 것.**

---

## 1. 담당 배정 (후보)

T4 16GB에 들어가는 것 위주로 골랐다. 괄호는 대략적인 가중치·메모리.

| 담당 | 모델 | 논문 | 특징 | T4 |
|---|---|---|---|---|
| A | **IDM-VTON** | arXiv 2403.05139 | SDXL 기반. 예전에 "더 낫지만 무겁다"고 기각했던 모델(F절) | 29GB 다운로드, offload 필요 |
| B | **OOTDiffusion** | arXiv 2403.01779 | SD1.5 기반, 가볍고 인용 많음 | 여유 |
| C | **StableVITON** | CVPR 2024 | SD1.5 기반, 옷 정렬(warping) 방식이 다름 | 여유 |
| D | **Leffa** | Meta, 2024 | 어텐션을 옷 쪽으로 흐르게 해 디테일 보존 | 보통 |

바꿔도 된다. 다만 **FLUX·Qwen 계열(120억~200억 파라미터)은 T4에 안 들어간다.** 그건 나중에 A100을 빌려서 한다.
고를 때 확인할 것: ① 코드와 가중치가 공개돼 있는가 ② 추론 코드가 있는가(학습 코드만 있으면 제외) ③ T4 16GB에 들어가는가.

## 2. 바꾸지 말 것 (공통 입력)

Kaggle 데이터셋 `jefferyjung/vfa-person-full`, `vfa-set2`, `vfa-real-garments` 에 다 있다.

**인물 1명** — `person_team02.jpg` (2026-09-21 촬영, 가이드대로 크롭. 인물 비율 0.746)

**옷 4벌**
| 이름 | 파일 | 왜 이 옷인가 |
|---|---|---|
| 블루 셔츠 | `garment_shirt_blue.jpg` | 긴팔·단추·칼라. 형태가 복잡함 |
| 카키 반팔 | `garment_tee_khaki.jpg` | 단색. 기본 성능 확인 |
| 오랑우탄 프린트 티 | `tshirts.jpg` | **사진 프린트 + 흰 옷.** 가장 어려운 조건 |
| 네이비 코듀로이 바지 | `pants.jpg` | 하의. 질감 있는 옷 |

**시드 2개**: 42, 123 — 시드 하나로 판단하면 안 된다. 같은 설정에서 시드만 바꿔도 결과가 갈린 전례가 있다.

→ 한 모델당 **8장** (옷 4벌 × 시드 2개). 하의를 지원하지 않는 모델이면 상의 3벌 × 2시드 = 6장.

## 3. 측정 항목

### 숫자 (커널이 자동으로 CSV에 기록)
| 항목 | 방법 |
|---|---|
| **장당 시간(초)** | 워밍업 1장을 버리고 측정. 모델 로딩·설치 시간은 따로 |
| **최대 GPU 메모리(GB)** | `torch.cuda.max_memory_allocated()` |
| 모델 로딩 시간(초) | 가중치를 GPU에 올리는 데 걸린 시간 |
| 가중치 용량(GB) | 다운로드 총량 |
| 출력 해상도 | 예: 576x768 |
| 설치 성공 여부 | 막힌 지점과 해결책을 `docs/ENVIRONMENT.md` 형식으로 적을 것 |

### 품질 (눈으로 판정, 8장 각각)
아래 6개 항목을 **O / △ / X** 로 적는다. 원본 옷 사진과 나란히 놓고 볼 것.

| 항목 | O 기준 |
|---|---|
| **색** | 원본 옷 색과 같다 (연해지거나 톤이 바뀌지 않음) |
| **프린트·무늬** | 그림/글자의 형태가 알아볼 수 있게 나온다 |
| **실루엣** | 소매 길이·기장·품이 원본 옷과 같다 |
| **없던 것** | 원본에 없는 주머니·덮개·단추가 생기지 않았다 |
| **원래 옷 흔적** | 입고 있던 옷이 비치거나 남지 않았다 |
| **사람·배경 보존** | 얼굴·손·바지·배경이 뭉개지지 않았다 |

**판정은 반드시 원본 해상도로 잘라서 볼 것.** 썸네일로 보고 "괜찮다"고 했다가 뒤집힌 적이 있다(F-7).

## 4. 커널 만들기

`kaggle_model_template/run_template.py` 를 복사해서 쓴다. 측정·CSV·입력 찾기가 이미 들어 있고,
**TODO 표시된 3곳**(설치, 모델 로딩, 추론 호출)만 맡은 모델에 맞게 채우면 된다.

```sh
cp -r kaggle_model_template kaggle_<모델이름>
# run_template.py 를 run_<모델이름>.py 로 바꾸고 kernel-metadata.json 의 id/title/code_file 수정
PYTHONUTF8=1 kaggle kernels push -p kaggle_<모델이름> --accelerator NvidiaTeslaT4
PYTHONUTF8=1 kaggle kernels status jefferyjung/vfa-<모델이름>
```

### 자주 걸리는 함정 (이미 겪은 것들)
- **`PYTHONUTF8=1` 없으면** 한글 때문에 cp949 오류가 난다(Windows).
- **clone·가중치는 `/kaggle/tmp`, 결과만 `/kaggle/working`.** 안 그러면 output이 수천 개 파일이 된다.
- **정밀도를 직접 지정할 것.** T4·P100은 bf16을 흉내만 내서 가장 느리다. fp16이 fp32보다 4배 빠르고 결과는 같았다(F-13·F-14).
- **T4 메모리가 모자라면** CPU offload를 쓴다. 단 offload는 CPU RAM을 12GB 이상 먹어서 **GPU 2장 동시 사용이 안 된다**(F-15).
- **구버전 패키지를 깔면** Kaggle 기본 패키지와 충돌한다. 필요한 것만 최소로 고정할 것(F-15 v1 실패 사례).
- **실행 시간이 12시간을 넘으면** 커널이 죽는다. 8장이면 문제없다.

## 5. 제출물

각자 아래 셋을 낸다.

1. **커널 폴더** — `kaggle_<모델이름>/` (코드 + kernel-metadata.json)
2. **결과** — `results.csv` + 이미지 8장 (`data/samples/results/<모델이름>/`, 커밋하지 않고 공유 폴더로)
3. **한 장 요약** — `docs/PLAN.md` 에 넣을 형식으로. 아래 틀을 그대로 채운다

```markdown
### <모델 이름> (담당: 이름, 날짜)

논문/저장소: <링크>. 구조 한 줄 설명. 라이선스.
커널 `kaggle_<이름>/`, 설정: <정밀도·스텝·guidance 등>

| 항목 | 값 |
|---|---|
| 장당 시간 | ○초 (T4) |
| 최대 GPU 메모리 | ○GB |
| 가중치 용량 | ○GB |
| 출력 해상도 | ○x○ |

품질 (8장): 색 ○/8, 프린트 ○/8, 실루엣 ○/8, 없던 것 ○/8, 원래 옷 흔적 ○/8, 보존 ○/8

- 잘 된 점:
- 안 된 점:
- 설치하며 막힌 곳과 해결:
- **판단: FASHN과 비교해 (더 낫다 / 비슷하다 / 못하다). 이유:**
```
