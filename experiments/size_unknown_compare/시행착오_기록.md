# FitCheck 치수 예측 시행착오 기록

치수를 모르는 사용자를 위해 성별·키·몸무게로 가슴·허리·어깨를 예측하는 작업의 기록이다. 새로운 시행착오가 생기면 아래에 이어서 적는다.

## 현재 결론 (2026-11-09)

- 앱 후보는 항과 나이를 넣은 선형 회귀다. 나이를 넣은 MLP와의 오차 차이는 0.02cm 이내였다.
- 모델을 바꾸는 것보다 입력을 늘리는 효과가 컸다. 항을 넣은 모델에 나이를 추가하면 허리 오차가 3.10cm에서 2.59cm로 줄었다.
- 나이는 상의 사이즈 일치율을 올리지 못했다. 남성 기준 74.5%에서 74.4%로 사실상 같다.
- 어깨 입력은 사이즈코리아 `어깨사이길이`에 더 가까워 보인다. 치수 정의는 교수님 자문으로 확인이 필요하다.
- 예측 치수로 추천할 때 1등과 2등의 점수 차가 2.0 미만이면 경계로 안내하는 것을 제안한다. 유니클로 표 기준값이며 앱에는 아직 넣지 않았다.

## 기록

### 1. 강화학습을 쓸지 검토
- **시도:** 예외처리 방법으로 강화학습과 딥러닝을 후보로 놓았다.
- **문제:** 정답 치수가 있는 예측 문제라 행동과 보상을 억지로 만들어야 한다.
- **조치:** 강화학습을 제외하고, 정답 데이터로 학습하는 회귀 문제로 정했다.

### 2. 논문을 "선형 회귀가 딥러닝보다 낫다"로 읽을 뻔함
- **시도:** Bartol et al.(Sensors 2022)을 근거로 선형 회귀를 우선 후보로 놓았다.
- **문제:** 논문의 딥러닝 경쟁 모델은 주로 사진이나 3D 스캔을 입력으로 쓴다. 키·몸무게만 넣은 신경망과 같은 입력으로 비교한 실험은 없었다.
- **조치:** 같은 입력으로 직접 비교하는 실험을 설계했다. 처음 제안한 그래디언트 부스팅은 빼고, 논문처럼 항을 추가한 선형 회귀를 넣었다.

### 3. 데이터 자동 다운로드 실패
- **시도:** 사이즈코리아 페이지와 파일을 스크립트로 받으려 했다.
- **문제:** 인증서 검사를 끈 요청과, 다운로드 목적 선택 창을 건너뛰는 직접 요청이 도구의 안전 규칙에 막혔다.
- **조치:** 팀원이 사이트 화면에서 직접 받았다. 공개용 파일에 개인별 직접측정 자료가 있었다.

### 4. 엑셀 한글 깨짐
- **시도:** 격리 실행 옵션(`python -I`)으로 파일 구조를 출력했다.
- **문제:** 이 옵션은 환경 변수를 무시해 출력 인코딩 설정이 먹지 않았고, 한글 열 이름이 깨져 보였다.
- **조치:** 코드에서 출력 인코딩을 UTF-8로 직접 지정했다. 파일 자체에는 문제가 없었다.

### 5. 결측 코드가 숫자로 섞여 있음
- **문제:** 여성 1명의 `어깨사이길이`가 999.9cm였다. 실제 값이 아니라 결측 코드로 판단했다.
- **조치:** 그 항목에서만 이 값을 제외했다. 평균만 보면 놓치기 쉬워서 평균에서 크게 벗어난 값을 먼저 출력해 확인했다.

### 6. 어깨 기준을 잘못 고를 뻔함
- **시도:** 앱 설명이 "어깨 끝점 사이 직선"이라서 `어깨너비`를 기준으로 삼으려 했다.
- **문제:** 가슴둘레 102~106cm 남성 510명 중 `어깨너비`가 46cm 이상인 사람은 0%였다. 실제 착용 모델의 입력값은 46cm다. 같은 집단의 `어깨사이길이`는 46cm 이상이 31.2%였다.
- **조치:** 두 항목을 모두 평가했다. 앱 척도에는 `어깨사이길이`가 더 가까워 보이지만, 한 사람의 사례에서 나온 추정이라 정의 확인이 필요하다.

### 7. 여성 사이즈 일치율이 높아 보이는 착시
- **문제:** 여성 일치율은 약 93%지만, 모두에게 M만 추천해도 88.2%가 나온다. 쓸 수 있는 치수표가 M·L·XL뿐이기 때문이다.
- **조치:** 일치율을 항상 "최다 사이즈만 추천"한 값과 나란히 보고한다. 남성은 그 값이 42.4%, 항을 추가한 선형 회귀가 74.5%라 차이가 더 분명하다.

### 8. 모델보다 입력 정보가 중요했음
- **결과:** 항을 추가한 선형 회귀와 MLP의 차이는 대부분 0.01cm 이내였다. 나이를 추가했을 때 허리 오차는 0.53cm 줄었다. 가슴과 어깨 오차는 거의 그대로였다.
- **조치:** 항을 추가한 선형 회귀와 MLP 양쪽에 나이를 넣어 다시 비교했다.

### 9. 나이가 상의 추천까지 개선할 것으로 기대함
- **시도:** 허리 오차가 크게 줄어서 사이즈 추천 전체가 좋아질 것으로 기대했다.
- **문제:** 상의 점수식은 가슴과 어깨만 쓰는데, 나이를 넣어도 가슴 오차는 0.01cm, 어깨사이길이 오차는 0.02cm만 줄었다. 남성 일치율은 74.5%에서 74.4%로 사실상 같았다.
- **조치:** 나이의 효과를 "허리 치수 개선"으로만 보고한다. 하의 추천 개선은 하의 치수표로 평가하기 전까지 주장하지 않는다.

### 10. 사이즈 하나만 추천하면 경계에서 결과가 뒤집힘
- **시도:** 남성 입력 사례 하나로 유니클로 반팔 추천을 시험했다. 몸 치수는 개인정보라 입력값은 적지 않는다.
- **문제:** 예측 치수 기준 점수는 L 2.2, M 2.4로 L 추천이었다. 그런데 실제 예측 오차를 반영하면 M 53.9%, L 44.5%였고, 체격과 나이가 비슷한 실제 측정자 73명도 M 45명, L 26명, XL 2명이었다. `어깨너비` 기준으로 계산하면 추천이 M으로 바뀌었다.
- **조치:** 점수 차이가 작으면 한 사이즈만 단정하지 말고 "M/L 경계"로 안내하는 방향을 제안했다. 기준값은 11번에서 정했다.

### 11. 경계 기준값을 정해 보니 옷마다 다시 봐야 함
- **시도:** 단정한 사람의 사이즈 일치율 85% 이상을 기본 목표로 정하고, 1등과 2등의 점수 차 기준값을 처음 보는 사람들로 검증했다. 기준값은 남성 분포로 골랐다.
- **결과:** 기준값은 2.0이었다. 중첩 검증에서 남성의 41.9%가 경계로 분류됐고, 단정한 사람의 일치율은 85.2%였다. 경계 안내 전 전체 일치율은 74.4%였다. 여성은 11.2%가 경계로 분류됐고 단정 일치율은 97.2%였다.
- **문제 1:** 치수표를 가상으로 바꾸면 다시 고른 기준값이 1.2~2.5로 움직였다. 고정값 2.0을 그대로 쓰면 단정 일치율은 83.5~87.6%였다.
- **문제 2:** 입력 오차를 넣으면 단정 일치율이 83.4%, 나이를 비우면 84.1%로 목표보다 조금 낮았다.
- **문제 3:** 이 기준값은 예측 치수의 오차로 정한 값이라, 사용자가 실제 치수를 입력한 경우에는 쓰면 안 된다.
- **조치:** 복잡한 확률 규칙은 같은 경계 비율에서 점수 차 규칙과 거의 같아서 점수 차 규칙을 유지한다. 2.0은 이 유니클로 표의 기준값으로 기록하고, 다른 옷은 다시 확인한다.

### 12. 팀 저장소를 늦게 확인해 같은 주제를 따로 진행함
- **문제:** 실험을 마치고 업로드할 때에야 PR #5를 발견했다. 같은 논문과 같은 사이즈코리아 데이터로 치수를 모를 때의 추천을 이미 앱 코드까지 구현한 PR이었다. "앱 코드가 PC에 없다"고 판단하고 GitHub를 먼저 찾아보지 않은 것이 원인이다.
- **차이:** PR #5는 키·몸무게 선형 회귀와 확률 기반 추천을 쓰고, 어깨는 앱 안내와 같은 `어깨너비`, 가슴은 `젖가슴둘레`를 쓴다. 이 실험은 MLP 비교, 나이와 추가 항의 효과, 점수 차 경계 기준, `가슴둘레`와 `어깨사이길이` 평가를 다룬다.
- **미해결:** 어느 치수 정의가 앱 입력과 치수표에 맞는지는 아직 결론이 없다. 이 실험의 수치는 PR #5와 치수 정의, 평가 치수표가 달라 그대로 비교할 수 없다.
- **조치:** 앱 코드를 건드리지 않고 실험 기록으로만 올린다. 팀이 PR #5와 합칠 내용을 정한다.

## 실험 조건

- **데이터:** 사이즈코리아 8차 1~2차년도 직접측정, 20~69세 5,092명 (남 2,319명, 여 2,773명)
- **검증:** 5겹 교차검증을 3회 반복. 모든 모델이 같은 분할을 쓴다. MLP 설정은 학습 데이터 안에서만 골랐다.
- **MLP:** 은닉층 3종과 정규화 2종, 총 6개 설정 중 선택. 시드 5개 평균
- **입력 오차 시험:** 키에 표준편차 1cm, 몸무게에 표준편차 1.5kg의 무작위 오차를 추가

## 한계

- 일치율의 정답은 실제 착용감이 아니라 실제 치수를 현재 점수식에 넣어 고른 사이즈다.
- 유니클로 반팔 한 벌의 M·L·XL만 평가했다. 다른 옷이나 다른 사이즈 범위에서는 값이 달라질 수 있다.
- 입력 키와 몸무게는 실측값이다. 자기 신고 오차는 무작위 오차로만 흉내 냈고, 몸무게를 한쪽으로 치우치게 적는 경향은 반영하지 않았다.
- 하의 치수표가 없어 허리 예측이 하의 추천을 얼마나 바꾸는지는 평가하지 않았다.
- `linear_coefficients.json`에 세 선형 모델의 계수를 저장했지만, 아직 앱 코드에는 넣지 않았다. 저장 계수로 다시 계산한 값은 모델 예측과 일치함을 확인했다.

## 파일

- `prepare_data.py`: 원본 엑셀에서 필요한 열을 뽑고 데이터를 점검한다.
- `run_comparison.py`: 모델을 비교한다.
- `predict_example.py`: 한 사람의 치수와 사이즈를 예측한다.
- `tune_boundary.py`: 경계 안내 기준값을 정하고 검증한다. 로그는 `boundary_log.txt`
- `results/`: 항목별 오차, 일치율, 계수
- `results_log.txt`: 실행 로그 전체
